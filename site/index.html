01 / METHOD

On Pons the contract is always clean.
The people aren't.

Every Pons token uses the same audited template: you can always buy and sell, there is no blacklist, no hidden mint. A scanner that only reads the contract will call every token safe. What changes from one token to the next is the story it tells and the wallets behind it, so that is what Hoodwink checks.

03 / REALITY CHECK

Every link they typed
is on the chain. We open them.

The description, website, X and Telegram links a creator types on Pons are stored in the launch transaction. Hoodwink reads them, visits the site, reads the X post, looks up the GitHub, then hands the whole file to an AI that answers one question: does the evidence back the story?

04 / LOOK-ALIKES

There is one real NVDA.
Copies get caught.

Tickers get copied within minutes of a launch that works. Hoodwink keeps an index of every Pons ticker, so it can tell you whether you are looking at the original or copy number seven. Stock tickers are checked the same way: every official Robinhood stock token runs the same 283-byte proxy, so a memecoin borrowing NVDA or a pair priced in a fake stock is caught on the first read.

06 / RULES

Four rules the scanner never breaks.

R1

Unchecked is never a pass.

When a source is unavailable or a question cannot be answered, the check says so and stays out of the coverage. A green row only covers the exact thing it measured.

R2

Coverage is not a safety score.

The percentage tells you how much of the investigation completed. It never adds up into a "safe" badge. You read the findings and decide.

R3

The AI only judges evidence.

The verdict is written from what the scanner found: the launch metadata, the fetched site, the post, the repository. It cannot be fed text by the person asking, and it must name the item behind each flag.

R4

No wallet, nothing broadcast.

The chain is read from your browser through the public RPC; our server only opens the links (your browser is not allowed to). There is no connect button, and the contract test is a simulation that never leaves the node.
